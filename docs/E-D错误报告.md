# PN-D（0.8234）该怎么优化：结论与方案

## 先说诊断结论（有实测证据）

1. **PN-D 和 B3331 是同一人**（黑色T恤黑裤男性，视觉确认 + 特征相似度 0.975），应该就是赖国伟本人。
2. **根因：ReID 模型在这批门铃画面上几乎没有区分度**：
   - 不同人之间的余弦高达 0.84~0.96（B3331↔D011850=0.964）；
   - 同人之间反而更低（B3331↔E-D=0.840）；
   - 一个**不同的人**（E-D，女性蓝衣）对赖国伟库项得分 **0.8886**，比**本人** PN-D 的 0.8234 还高。
3. 因此 **PN-D 的 0.8234 不是阈值能救的**：把阈值降到 0.82 能放行 PN-D，但同时会放行 4/5 个陌生人（0.83~0.88）。这是特征空间塌缩，不是阈值问题。

## 优化方案（按优先级）

**① 治本：接入人脸识别作为主身份信号（最推荐）**
- 门铃视频人正对镜头，人脸跨人区分度远高于 ReID（同一人 ~0.7+，不同人通常 <0.3）。
- 你的 `models/` 里已有 `scrfd_10g.onnx`、`glintr100.onnx`、`w600k_r50.onnx`，同仓库的 FaceFeature 项目已经有完整的人脸检测→质量筛选→识别链路，可以移植/融合进来。这是能让 PN-D 和陌生人干净分开的正解。

**② 治本（次选）：换/微调 ReID 模型 + 提高裁剪质量**
- 当前模型在低清门铃小目标上失效（B3331 人框只有 78×225，还有很多黑边）。
- 换针对监控场景的模型，或拿自家门铃数据微调；检测框加 margin、必要时超分。

**③ 工程上最现实：重建 Gallery —— 同一人多段注册**
- 现状"赖国伟-背面/正面"是两条，先合并成一条"赖国伟"（消除 margin 歧义）；
- 用**同一名字"赖国伟"注册 3~5 段不同角度/光线/服装的代表视频**，特征 EMA 叠加，让库项覆盖更全。
