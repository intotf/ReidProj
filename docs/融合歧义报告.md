# 结论

**不是分数不够高，而是"歧义判定（margin）"没通过。** 你的 0.8248 已经通过了命中阈值（`> 0.62`），但代码还要求 **最高分 − 次高分 > 0.08**。你这次匹配失败，是因为 Gallery 里同一个物理人注册了多个成员（正面/背面），导致最高分和次高分几乎一样高，系统判定"分不清是谁"，于是返回 `stranger`。

# 建议修复（按优先级）

1. **数据去重（治本）**
   同一个物理人只保留一个 Gallery 成员。`FamilyGalleryService.EnrollAsync` 已经按 `Name` 去重并做 EMA 合并（`G:\Github\Jiulang\ReidProj\ReidFeature\Services\FamilyGalleryService.cs`），所以注册时用**同一个 memberName**（比如都叫"赖国伟"，不要带"-正面/-背面"）就能自动合并；或者把现有两条记录删掉一条。

2. **放宽/改造 margin 判定**
   目前 `bestScore − secondBestScore > 0.08` 对多模态融合（各子分都压缩在 0.9 附近）太苛刻，且对"同一人多注册"零容忍。可改为：
   - 最高分很高（如 > 0.80）时直接命中；
   - 或相对 margin：`(best − second) / best > 0.08`；
   - 或把 0.08 做成可配置参数，先调成 0.04~0.05 观察。

3. **步态降权或门控**
   当两端步态信号无效/噪声大（采样点 < 3、频率异常）时把 `wGait` 置 0 并重新归一化其余权重，避免低可信步态分把总分拉低。

4. **日志补充次高分**
   现在 `Log.RecognitionResult` 只打 `name/score/trackId`，建议把 `secondBestScore` 和次佳成员名也打出来，下次直接能从日志确认"差了多少"。
