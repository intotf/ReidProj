# ReidFeature 识别系统：阈值含义与现存问题报告

日期：2026-08-06　范围：ReidFeature（服务）+ FamilyDiscern（客户端）实测结论

## 一、识别打分流程

视频裸流(H264/H265 Annex-B)
→ ffmpeg 流式解码（每 N 秒一帧，默认 0.5s）
→ YOLOv11n 人物检测（置信度 ≥ 0.20，NMS IoU 0.45）
→ ByteTrack 跟踪（IoU 匹配阈值 0.3；高/低置信度分界 0.5）
→ TrackFusion：取 bbox面积×检测置信度 最高的 Top-5 帧
　├─ 全身 ReID 特征（余弦相似度）
　├─ 头肩 ReID 特征（余弦相似度）
　├─ 体型标量（MoveNet 关键点 → 头身比/肩髋比，1/(1+距离)）
　└─ 步态标量（轨迹中心点 → 步频/摆幅，1/(1+距离)）
→ 与 Gallery 成员逐维相似度 → 加权融合总分
→ 判定：总分 > HitThreshold → 命中该成员；否则 stranger

## 二、各类阈值与参数的含义

| 参数 | 位置 | 当前值 | 含义 |
|---|---|---|---|
| HitThreshold（命中阈值） | Handlers/RecognizeHandler.cs | 0.965 | 四维融合相似度总分必须超过此值才判定命中；低于则返回 stranger。是"认不认识这个人"的最终闸门。 |
| wCloth / wHead / wBody / wGait（融合权重） | Payloads/TrackFeaturePack.cs 默认；调用方传参 | 默认 0.30/0.40/0.20/0.10；推荐 0.50/0.50/0/0 | 总分 = wCloth×全身 + wHead×头肩 + wBody×体型 + wGait×步态。权重决定"总分"的数值含义，换权重必须重标阈值。 |
| MarginThreshold（歧义差距） | RecognizeHandler.cs（已移除，原 0.08） | 无 | 原要求"最高分 − 次高分 > 0.08"才命中，防多成员相似时乱认。因同一人重复注册（背面/正面）导致本人全被拒，已移除；现只靠 HitThreshold 一道闸门。 |
| YOLO 检测置信度 | Services/YoloDetector.cs | 0.20 | 检测框置信度低于 0.20 丢弃，避免背景误检。 |
| YOLO NMS 阈值 | Services/YoloDetector.cs | 0.45 | 非极大值抑制：两框 IoU > 0.45 保留高分框。 |
| ByteTrack 匹配阈值 | Services/ByteTrackTracker.cs | 0.3（IoU） | 相邻帧检测框 IoU ≥ 0.3 视为同一目标。 |
| ByteTrack 高/低置信度分界 | Services/ByteTrackTracker.cs | 0.5 | ≥0.5 高置信度优先匹配，<0.5 低置信度策略。 |
| 姿态关键点置信度 | Services/PoseEstimator.cs | 0.3 | 关键点置信度 ≤0.3 视为无效；缺关键点则体型标量置 0。 |
| EMA 融合系数 | Services/FamilyGalleryService.cs | 0.3 | 同名重复注册：新特征 = 旧×0.7 + 新×0.3。决定"多段注册"能否覆盖新视角。 |
| MaxRequestBodySize | Program.cs | 100MB | 请求体上限（原 20MB，为批量多段注册放大）。 |
| 相似度公式 | Payloads/TrackFeaturePack.cs | — | 全身/头肩用余弦；体型/步态用 1/(1+欧氏距离)。 |

## 三、权重与阈值的相互作用（理解重点）

总分 = wCloth×全身 + wHead×头肩 + wBody×体型 + wGait×步态

- 权重不同，同一个视频的"总分"数值含义完全不同：
  - 30/30/30/10 下，注册源视频自匹配只有 0.86（体型 0.87、步态 0.06 把 0.99 的全身/头肩拖下来）；
  - 50/50/0/0（去掉体型/步态）下，同一视频自匹配升到 0.989。
- 因此 HitThreshold 必须和权重、当前 gallery 一起标定，不存在"一个万能阈值"。
- 本次实测标定结果（生产库=单条融合"赖国伟"，10 视频）：

| 配置 | 成员命中 | 陌生人误报 | 正确 |
|---|---|---|---|
| 0.88 + 30/30/30/10（旧现状） | 0/5 | 0/5 | 5/10 |
| 0.88 + 50/50/0/0 | 5/5 | 4/5 | 6/10 |
| 0.96 + 50/50/0/0 | 4/5 | 1/5 | 8/10 |
| 0.965 + 50/50/0/0（当前部署） | 4/5 | 0/5 | 9/10 |

## 四、现存问题

### 1. 模型区分度不足（根本问题）
- 门铃/监控低清小目标画面上，ReID 模型的跨人余弦高达 0.84~0.96，本人与陌生人在特征空间高度重叠。
- 实测反例：本人 PN-D 对库项 0.929，反而低于陌生人 D6504 的 0.956；本人 E-D 0.948 与两个陌生人 D1185/D3527（均 0.948）完全相等。
- 结论：任何单一阈值都无法做到"全部本人命中 + 全部陌生人拒绝"。0.965 已是本数据集上的折中最优（漏掉与陌生人不可区分的 E-D）。

### 2. 体型/步态维度在当前场景是"负资产"
- MoveNet 在低清小目标上体型标量噪声极大（同一人不同片段体型相似度 0.64~0.99），步态几乎无区分度。
- 它们把本人总分压低、又让部分陌生人分数反超本人。
- 处理：当前推荐去掉体型/步态（权重 50/50/0/0），只保留相对可靠的全身+头肩。

### 3. 阈值窗口极窄、脆弱
- 0.965 时，最近的陌生人 D1185=0.9615，最低可命中的本人 B3331=0.9680，可用窗口只有约 0.006。
- 光线/角度/视频质量抖动 0.01 就可能把"命中"变"漏检"或引入误报。

### 4. E-D 无法匹配（成员身份存疑）
- E-D 视觉上为女性、蓝色T恤，与赖国伟（黑色T恤男性）明显不同人，但被用户标记为"成员视频"。
- 若 E-D 里是另一位家庭成员（如张小姐）→ 应单独注册成自己的成员；
- 若 E-D 是陌生人 → 0.965 拒绝它是正确的，但会与"它是成员"的预期冲突。

### 5. 注册/库项质量（历史问题，已修复）
- 最初的 2 段注册（EMA 顺序/可能的轨迹选取问题）导致注册源视频 #2 自己都匹配不上（0.84 < 0.88）。
- 已通过"删除旧条目 + enroll-batch 等权融合重注册"修复，现在自匹配 0.989。
- 教训：enroll-batch 同名注册走的是 EMA(0.3) 合并，不会覆盖旧特征；要"重新注册"必须先删除再批量注册。

### 6. 阈值与库项强耦合，换库需重标
- 0.88 是按旧库（赖国伟-背面/正面 两条）标定的；换成新库（单条融合）后全部失效。
- 每次增删/重注册成员后，都应重新跑一遍测试集标定阈值。

### 7. 工程/部署不一致
- 服务只支持 H264/H265 裸流：MP4 容器直接 POST 会返回 null（解码嗅探失败），调用方必须先转裸流（FamilyDiscern 已处理，curl 直调需注意）。
- 生产 V4 已部署 0.965，但 FamilyDiscern 默认权重仍是 30/30/30/10 未同步：不改成 50/50/0/0，识别要么全漏（本人 0.81~0.86<0.965）、要么（若只改权重不提阈值）全误报。
- margin 移除后没有"多成员相似歧义"保护：多个不同成员长相接近时，系统直接取最高分那个，不再拒绝。

### 8. 多条目/命名不稳定
- 若同一人保留多条记录（赖国伟-背面/正面），命中结果可能在不同 ID/名称间跳动；建议用 merge 接口合并去重。

## 五、现状与建议

### 当前生效配置（生产 V4，端口 9000）
- 判定：无 margin，HitThreshold = 0.965（已发布并验证：B3331 命中 0.968、D1185 拒绝 0.9615）。
- 调用需传权重：wCloth=0.50, wHead=0.50, wBody=0, wGait=0。

### 后续建议（按优先级）
1. 同步 FamilyDiscern 默认权重为 50/50/0/0（否则当前部署无法正常识别）。
2. 给 E-D 对应的人单独注册成员（确认其身份后），消除"漏检成员"。
3. 给"赖国伟"补注册更多视角（把 B3331/PN-D 等本人视频并进库项），提高本人分数、加宽阈值窗口。
4. 阈值参数化（配置项/查询参数），避免每次标定都改代码重发布。
5. 治本：接入人脸识别（models 已有 scrfd/glintr100/w600k）或换/微调更适合门铃场景的 ReID 模型。
